# 同城-骑手散单运营 - 知识沉淀

> 业务域ID: `rider_casual_operation`
> 语义模型: `knowledge/domains/rider_casual_operation.json`

---

## 一、领域概览 (Domain Overview)

**业务域**: 同城-骑手散单运营
**核心问题**: 统计每位同城骑手在2026年4月份的纯散件和月结散件收派件总量
**业务目标**: 为骑手分层运营策略提供数据依据，确定收件权限限制的优先级与范围

### 业务背景
- 仅高级骑手可接收全部类型散单（含下靠散单）
- 中级及以下等级骑手不得收取纯散和月结散类型的下沉单
- 此调整源于总裁要求：为提升面客质量，未来仅优质骑手具备完整收件权

## 四、关系拓扑 (Relationship Topology)

```
                    1:1
    Rider ────────────── Department
       │                     │
       │ 1:N                 │
       ├────────── AOIAssignment (1骑手:N区域)
       │
       │ 1:N                 N:1
       ├────────── Waybill ───── MonthlyCustomer
       │  (收件/派件)
       │
       │ 1:1
       └────────── SandStat (统计结果)
```

| 关系 | 基数 | 关联条件 | 语义 |
|------|------|---------|------|
| Rider → Department | 1:1 | `emp_code = login_id` | 骑手归属唯一网点（去重取最新） |
| Rider → AOIAssignment | 1:N | `emp_code = emp_code` | 骑手可配置多个AOI服务区域 |
| Rider → PickupWaybill | 1:N | `emp_code = emp_code` | 骑手可有多条收件运单 |
| Rider → DeliverWaybill | 1:N | `emp_code = emp_code` | 骑手可有多条派件运单 |
| Waybill → MonthlyCustomer | N:1 | `freight_monthly_acct_code = customer_code` | 运单通过月结卡号关联月结标签 |
| Rider → SandStat | 1:1 | `emp_code = emp_code` | 统计结果与骑手一一对应 |

## 五、公理 (Axioms)

| 编号 | 公理 | 形式化描述 | 业务含义 |
|------|------|-----------|---------|
| AX-001 | 运单唯一归属 | ∀w ∈ Waybill, ∃!k ∈ Rider: w.emp_code = k.emp_code | 每条运单必然且仅关联一个骑手 |
| AX-002 | 网点唯一性 | 同一骑手在同一分区中只属于一个网点 | 骑手不会同时归属多个网点 |
| AX-003 | 散单分类互斥 | PureSand(w) XOR MonthlyCasual(w) XOR NonSand(w) | 一条运单只能属于一种散单类型 |
| AX-004 | 散单计数非负 | ∀s ∈ SandStat: s.pure_casual_cnt ≥ 0 ∧ s.monthly_casual_cnt ≥ 0 | 统计结果中的散单数不可能为负 |

## 六、业务规则 (Business Rules)

### 6.1 散单识别规则

| 散单类型 | 判定条件 | 来源字段 | 语义 |
|----------|---------|---------|------|
| **纯散件** | `layer_name IS NULL` | 运单打标表 | 下单手机号或月结卡号在销售系统中**无任何客户分层标签** |
| **月结散件** | `freight_monthly_acct_code ∈ 月结表.customer_code` 且 `cust_tier_label ∈ ('1.1','1.2','1.3','2.1','2.2')` | 运单表 + 月结客户表 | 下单月结卡号有**月结1.1~1.3/2.1~2.2**的标签 |
| **非散件** | `layer_name IS NOT NULL` 且不匹配月结 | - | 有客户分层标签但非月结客群 |

### 6.2 月结客户标签枚举

`dm_crm.dm_customer_allcust_info_df.cust_tier_label` 月结客群有效值：

| 标签值 | 含义 |
|--------|------|
| `1.1` | 月结一级分层-A |
| `1.2` | 月结一级分层-B |
| `1.3` | 月结一级分层-C |
| `2.1` | 月结二级分层-A |
| `2.2` | 月结二级分层-B |

### 6.3 维度映射规则

| 维度 | 规则 | 说明 |
|------|------|------|
| **网点映射** | `login_id = emp_code`，过滤 `job_status=1 AND is_deleted=0`，按 `update_time` 降序取第一条 | 骑手维度表去重取最新在职记录 |
| **服务区域** | `concat_ws(',', collect_set(aoi_area_id))` GROUP BY `emp_code`，过滤 `status=1` | 骑手AOI区域去重后逗号拼接 |

## 七、度量体系 (Metric System)

| 指标名 | 定义 | 计算式 | 单位 | 预警阈值 |
|--------|------|--------|------|---------|
| **纯散件总数** | 骑手4月收派件中layer_name为空的运单总数 | `COUNT(layer_name IS NULL)` 收派合计 | 件 | - |
| **月结散件总数** | 骑手4月收派件中匹配月结客户表且月结标签有效的运单总数 | `COUNT(匹配月结)` 收派合计 | 件 | - |
| **散单骑手占比** | 有散单数据的骑手数 / 骑手基表总数 | `COUNT(pure_casual_cnt+monthly_casual_cnt>0) / COUNT(rider) * 100%` | % | 低于10%需人工复核 |

### 计算链路

```
pure_casual_pickup   (收件纯散计数) ──┐
                                    ├── ADD ── pure_casual_cnt (纯散合计)
pure_casual_deliver  (派件纯散计数) ──┘

monthly_casual_pickup     (收件月结散计数) ──┐
                                    ├── ADD ── monthly_casual_cnt (月结散合计)
monthly_casual_deliver    (派件月结散计数) ──┘
```

## 八、分区策略 (Partition Strategy)

| 数据源 | 分区条件 | 说明 |
|--------|---------|------|
| 骑手基表 | `inc_day='202604'` | 固定取202604月度分区 |
| 运单表 | `inc_day BETWEEN '20260401' AND '20260430'` | 4月全量 |
| 骑手维度表 | `inc_day='$[time(yyyyMMdd,-1d)]'` | 取T-1分区 |
| AOI分组表 | `inc_day='$[time(yyyyMMdd,-1d)]'` | 取T-1分区 |
| 月结客户表 | `max(inc_day)` | 取最新分区 |

## 九、编码约定沉淀

### 9.1 运单宽表分区过滤规范

月度范围查询应写为：
```sql
where inc_day >= '20260401' and inc_day <= '20260430'
```
**禁止使用** `substr(inc_day, 1, 6) = '202604'`，会导致全表扫描无法走分区裁剪。

### 9.2 月结客户表取最新分区

```sql
where inc_day = (select max(inc_day) from dm_crm.dm_customer_allcust_info_df)
```
使用子查询取最新分区而非写死日期，保证数据时效性。

### 9.3 骑手维度表去重模式

```sql
row_number() over (partition by login_id order by update_time desc) as rn
where rn = 1 and job_status = 1 and is_deleted = 0
```
此模式可复用于所有需要"取骑手最新网点"的场景。

### 9.4 AOI聚合模式

```sql
concat_ws(',', collect_set(aoi_area_id))
```
使用 `collect_set` 而非 `collect_list`，自动去重重复区域编码。

## 十、注意事项

1. **收发运单可能交叉**：同一运单号在收件宽表和派件宽表中均可能出现（收件和派件各一条记录），散单统计时应**分别按收件/派件维度统计后再合并**，避免去重逻辑错误
2. **服务区域可能为空**：骑手可能未配置AOI区域，`left join` 后 `service_area` 为 null，需用 `coalesce` 处理
3. **网点编码可能不匹配**：骑手维度表中 `login_id` 与骑手表 `emp_code` 可能存在编码不一致，需关注关联丢失率
4. **收件权限业务约束**：仅高级骑手(rider_level=4)可收全部散单，中级及以下不得收纯散和月结散下沉单——此约束在统计结果中可用于后续权限管控
