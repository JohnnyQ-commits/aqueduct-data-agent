### Added

- **Business-phrase retrieval in history search (中文业务表述检索修复 — 沉淀层闭环的前置)**: the mandated Phase 1 retrieval step (`history.py`) was table-name-only in practice — a Chinese business phrase embedded in a longer phrase could never match, because `search_history` built `\b<term>\b` word-boundary patterns and Chinese characters are all `\w` (no boundary exists between 率 and 及, so 「上岗率」 never matched 「上岗率及效能统计」). Verified live against the internal repo before the fix: the phrase hit nothing while `grep` found it in 10+ files of the delivering history — the exact "already implemented elsewhere, asked/re-implemented anyway" pain the retrieval layer exists to prevent. Pattern construction now branches on `str.isascii()`: ASCII terms keep word boundaries (ads_order must not substring-match ads_order_detail), non-ASCII terms degrade to escaped substring matching (case-insensitivity is a no-op for CJK but harmless for mixed terms). The data-developer Phase 1 prose and the change-management Phase 1 now also mandate passing 需求中的业务表述 (Chinese metric/report names) as positional search args alongside `--doc`'s table-name extraction, and change-management adds the light "新业务表述检索" step (search before asking or re-implementing — the ask-only-if-retrieval-fails layer). 3 new tests (`tests/test_search_history.py::TestCjkPhraseSearch`: CJK substring hit on md+json, SQL-comment hit with insert-extraction isolation, ASCII boundary preserved); suite at 887

- **Scorecard review findings broken down by review dimension (记分卡按维度细分 — 守门时能看单一维度退化)**: the eval scorecard's 审查发现 column counted Critical/Warning/Confirm as three merged totals, but PERF-11 already splits the review into 3 dimensions (需求与设计对齐 / 逻辑正确性 / 规范与影响) — a regression isolated to one lens (e.g. a template change that degrades 需求覆盖度) was invisible in C/W totals, and the cross-run variance data (same case: 20 vs 16 confirms, 3 vs 0 warnings) says gates should be read per-dimension, not as single values. Attribution now rides the review issue itself: `_parse_review_issues` scans line-by-line and tags every parsed issue with the dimension of the nearest preceding `## 维度审查: <名>` section header (issues outside any header — the single-block fallback path when dimension splitting degrades — get an empty dimension), while the two deterministic lenses are tagged at source: lint issues → `规范`（the linter *is* the deterministic standards lens）, trial-run failures → `试跑`. `CaseScore` gains `review_by_dimension` (dimension → {critical, warning}; dimension-less legacy issues bucket to 综合; no review run = empty dict — additive, the merged C/W/确认 column and evals scorecard metric are unchanged), and the report's per-case 明细 section renders a 审查维度 breakdown table only when findings exist (no empty shell). 6 new tests (`tests/test_review_split.py`: section-header attribution, headerless fallback, lint/trial source tagging; `tests/test_evals.py`: breakdown counts + rendering, absent-render-nothing); suite at 884

- **linter golden set (语料级回归 — 好样本必过 + 坏样本必拦)**: the 7 ERROR rules each had rule-level unit tests (single-shape fixtures in test_validator.py), but nothing guarded the *corpus* — a calibration change (e.g. §7.2's CASE-guard tolerance adjustments) could flip behavior on a realistic full-pipeline script while every unit test still passed, because unit tests pin the shapes they were written for, not the shapes a whole ETL script mixes together. `evals/golden/` now carries a tracked, desensitized synthetic corpus with a `manifest.json` contract: **good/** samples must produce zero ERROR *and* zero WARN (weekly_stat_full_pipeline replicates the proven clean shape of a full CTAS→insert-overwrite ADS script with 宏字面量; case_guard_forms enumerates the six CASE-guard forms across the §7.2 calibration history — 零守护保 else / 正守护保 then / count(distinct) 分母 / 多行正守护 / is-null+正守护组合, the linter's historical false-positive hotspot; join_aggregate_style pins left-join ON + nullif-denominator style); **bad/** samples carry exactly one violation each, asserted by manifest-declared level + message substring (select *, uppercase keyword, unguarded division, CTE, forbidden partition, cross join, tmp_ prefix, plus guard-on-unrelated-column — the shape the §7.2 calibration itself proved must still be flagged). Coverage anchors pin that every on-disk .sql is manifest-listed (orphan detection) and that the bad set touches all 7 ERROR rules. 13 new tests (`tests/test_evals_golden.py`); suite at 878
