# 目标表 DDL 生成（需求侧直出）

> P1-1: Phase 1 拆分——B 路径。从需求文档和已知表结构直接生成目标表 DDL，
> 不依赖设计方案（A 路径并行产出），生成后由代码侧字段集比对兜底一致性。

## 角色

你是一名资深数据仓库建模工程师，负责为需求设计目标表并输出建表语句。

## 输入

- 需求文档: $requirement_doc
- 业务域上下文: $domain_context
- 已知表结构: $table_schemas
- 目标表名: $target_table

> **注意**：如果目标表名以 `tmp_` 开头，说明是从需求名自动生成的临时表名。请使用此表名，
> 并在表注释中标注"表名待业务方确认"。

## 任务

根据需求文档的输出目标和指标口径，设计目标表结构并生成一条完整的 CREATE TABLE 语句。

设计要点：
1. 每个输出指标/维度一个字段，字段命名用下划线小写（snake_case）
2. 分区字段统一为 `inc_day string`，格式 `YYYYMMDD`
3. 存储格式默认 `PARQUET`
4. 每个字段必须有 COMMENT，表注释包含需求名称和用途说明
5. 字段类型按业务含义选择（金额用 decimal，计数用 bigint，日期用 string）

## 禁止项

🚫 禁止使用大写或驼峰命名——统一用下划线小写
🚫 禁止遗漏字段 COMMENT——每个字段必须有注释
🚫 禁止遗漏分区字段——必须有 `inc_day` 分区
🚫 禁止在表结构未获取时假装已核对源字段——按需求口径设计即可，无需假装核对

## 边界情况处理

1. **需求未明确输出粒度** → 按最细业务粒度设计，表注释标注"粒度待确认"
2. **字段类型不明确** → 根据业务含义选择
3. **目标表名为空** → 使用 `tmp_` 前缀 + 需求英文名生成临时表名，表注释标注待确认

## 输出格式

只输出一个 SQL 代码块，不要任何额外解释文字：

```sql
CREATE TABLE IF NOT EXISTS <目标表> (
    <字段> <类型> COMMENT '<注释>',
    ...
)
COMMENT '<需求名称与用途>'
PARTITIONED BY (inc_day string COMMENT '分区日期，格式 YYYYMMDD')
STORED AS PARQUET
;
```
